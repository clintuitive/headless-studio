# Chapter 5 — Build a Sample Instrument from Your Own Sounds

A sampler plays recordings at different pitches. The recording may be a piano
note, a struck glass, a drum hit, or a tone generated by a program. Once the
sound exists as a WAV file, the player needs a map: which file should answer
this note, how fast should it play, and when should it stop?

This chapter builds that map using sounds we generate ourselves. You do not
need a commercial library or an undocumented file format.

## Make a small instrument

From the repository root, install the core dependencies and run:

```bash
python -m pip install -r requirements.txt
python scripts/generate_sampler_demo.py --output-dir Tracks/sampler-demo
```

The result is a folder containing an instrument and a short performance:

```text
Tracks/sampler-demo/
  demo.wav
  instrument/
    manifest.json
    provenance.json
    tone-48-soft.wav
    tone-48-bright.wav
    tone-60-soft.wav
    tone-60-bright.wav
    tone-72-soft.wav
    tone-72-bright.wav
```

The six recordings are synthesized by the script. Nothing is copied from a
factory library, and the example does not use a plugin. The complete runnable
implementation is `scripts/generate_sampler_demo.py`; the fragments below
explain its main decisions.

## A recording is an array

A sample rate of 44,100 means one second contains 44,100 amplitude values per
channel. To create two seconds of time coordinates:

```python
sample_rate = 44100
t = np.arange(sample_rate * 2, dtype=np.float64) / sample_rate
```

Each position in `t` is a time measured in seconds. A sine wave at frequency
`frequency` is `np.sin(2 * np.pi * frequency * t)`. Frequency is measured in
cycles per second. Doubling it raises the pitch by one octave.

MIDI note numbers give us a convenient pitch vocabulary. MIDI 69 is A at
440 Hz. Other pitches follow:

```python
frequency = 440 * 2 ** ((root - 69) / 12)
```

Twelve semitone steps multiply the frequency by two. We generate root notes
48, 60 and 72 so that the player can choose a nearby source instead of
stretching one recording across the entire keyboard.

## Give the sound a beginning and an ending

A tone that switches instantly from silence to a nonzero value can click.
An envelope changes amplitude over time. Our example uses a short attack and
a longer exponential decay:

```python
envelope = (1 - np.exp(-t / .008)) * np.exp(-t / .65)
```

The first factor rises from zero; the second falls toward zero. Their product
makes a struck, fading sound. The complete generator also fades the final
441 frames, or ten milliseconds, to zero so the source file ends smoothly.

For each pitch, we create two timbres:

```python
signal = .5 * envelope * (
    np.sin(2 * np.pi * frequency * t)
    + overtone * np.sin(4 * np.pi * frequency * t)
)
```

The second sine is an octave above the fundamental. Set `overtone` to `.08`
for the soft layer and `.3` for the bright layer. A harder played note can
therefore select a brighter recording, as well as receiving a different gain.
A real multi-sampled instrument often changes timbre much more substantially
between soft and hard playing.

SciPy writes the source as floating-point WAV:

```python
wavfile.write(path, sample_rate, signal.astype(np.float32))
```

This preserves working precision. It is not the final distribution format of
our albums; delivery formats and mastering are separate steps.

## Map each recording to a zone

A zone describes where a recording is used. Its key range selects pitches;
its velocity range selects how hard the note was played. Both ranges are
inclusive in this sampler.

```json
{
  "name": "Tone 60 soft",
  "root": 60,
  "keylo": 54,
  "keyhi": 65,
  "vello": 1,
  "velhi": 79,
  "group": "Synth tones",
  "file": "tone-60-soft.wav"
}
```

Put every zone in a list and save that list as `manifest.json`. The bright
version uses the same key range and velocities 80–127. The lower root covers
notes 0–53; the upper root covers notes 66–127. Those broad outer ranges keep
the demonstration simple, although extreme transposition will sound unnatural.

The `root` is the pitch actually recorded in the file. Playing MIDI 64 from a
root-60 recording requires faster playback, with ratio:

```python
ratio = 2 ** ((64 - 60) / 12)
```

That ratio is about 1.26. Source position advances by about 1.26 frames for
each output frame. Fractional positions require interpolation. Faster playback
also shortens the recording; pitch and duration are coupled in this simple
sampler. It is not a time-stretching instrument.

## Render a note

The shared engine exposes `ZoneSampler`. This is the same implementation that
`ExsSampler` is an equivalent alias used by the album renderer.
The engine reads the JSON manifest and WAVs. It loads the source recordings described by the manifest.

```python
from music_engine import ZoneSampler

sampler = ZoneSampler(
    "Tracks/sampler-demo/instrument",
    deterministic=True,
    stereo_output=True,
)
events = [
    (0, "on", 0, 64, 70),
    (round(0.6 * 44100), "off", 0, 64, 0),
]
audio = sampler.render(events, total_seconds=2.0)
```

Put this code in a file inside `scripts/`, or set `PYTHONPATH=scripts` before
running it elsewhere. The tuple fields are integer sample position, event kind,
channel, MIDI note and velocity. The note starts immediately and is released
at 0.6 seconds. The output has two channels and 88,200 frames.

The implementation converts a source file's sample rate before pitch shifting,
centers unsigned 8-bit PCM correctly, and can retain stereo sources. Those
small details prevent changes in pitch, DC offset and lost stereo information.
Our generated sources are mono, so stereo output duplicates them to both
channels; it does not invent stereo width.

A note-off starts the release envelope. A voice can also end because its
recording runs out. If another note starts while the first is sounding, their
arrays are added together. The engine pairs overlapping same-pitch notes in
first-in, first-out order; an optional sixth tuple field supplies a voice ID
when the score needs explicit pairing.

## Check the instrument by listening to its boundaries

The demo alternates soft and bright notes across the source roots. Try a
slower phrase that crosses MIDI 53 to 54 and 65 to 66. Those are places where
the selected source changes. Then play the same note at velocity 79 and 80.
You should hear the intended layer change without an accidental jump in level.

When building a larger instrument, record more root notes before relying on
extreme transposition. Match recording levels deliberately, trim starts with
care, and preserve enough decay for long notes. Several alternate recordings
can avoid repeated identical attacks. The current engine randomly selects
among equally matching zones unless `deterministic=True`; it is not a strict
round-robin player that guarantees each alternate is used in turn.

## Keep the source record with the instrument

The generator writes `provenance.json` with a description of the synthesis and
a SHA-256 hash for each WAV. The hashes establish which files were used. They
do not prove copyright ownership or grant permission for files from elsewhere.

For your own recordings, keep recording notes. For a third-party library,
keep the actual license and verify that it allows the intended use, including
redistribution if you plan to share the instrument itself. Permission to use a
sound in a finished composition is different from permission to publish its
individual samples or extract them for another player.

The project's MIT license covers its code and documentation. It does not
relicense plugin libraries or other external recordings.
For the current tutorial you need none of those: the generator, the manifest
and the sampler provide a complete example you can inspect and revise.
